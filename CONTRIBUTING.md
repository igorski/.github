# Contributing Guidelines 

Thank you for your interest in improving this project. Any effort spent to keep the project's features / maintenance of the repository sustainable for everyone involved is much appreciated.

## Issue & Communication Rules

To maintain repository security, strict rules regarding attachments and external links in issues and comments are enforced:

* **No External Links for Media:** Do not post external links to video players, file-sharing sites, or drives to demonstrate a bug. If you want to share a screenshot or screen recording, upload it **directly into the GitHub issue text box** using GitHub's secure, built-in media uploader.
* **No Compressed Files:** Archives like `.zip`, `.rar`, `.tar`, `.7z`, or executable files (like `.scr` or `.exe`) attached to issues are not allowed.
* **No Unsolicited Code Repositories:** Do not link to external "fixed clones" or private zip files containing code updates. All proposed code changes must be submitted transparently via a standard GitHub Pull Request.

Any issue comment or message containing suspicious external links or forbidden file attachments will be closed and locked immediately.

## Accepted contributions

Contributions that provide clear, functional value to the project are prioritized. Such contributions can be any of:

 * Fixing of documented bugs or security vulnerabilities
 * Implementing requested features or performance improvements
 * Adding tests or documentation where missing

## Not accepted contributions

To maintain a high signal-to-noise ratio and to minimize maintainer time, "low-impact" pull requests of the following type are not accepted:

 * Typos / grammar : changes to comments or documentation that do not affect clarity or correctness
 * Purely cosmetic changes: Code reformatting, changing whitespace or any type of adjustments that do not impact functionality or break builds
 * Farming: Pull requests that appear to be made solely to increase GitHub contribution stats without providing a tangible benefit to the codebase
 * Changes that do not adhere to the Security Policy

That you dedicate your time to contribute is much appreciated, but please understand the rationale behind the above list: maintaining these repositories also demands time from the maintainer.

If your PR does cover any of the points above and you feel that it significantly improves the project, you can always open an issue to discuss it.

## Pull Request process

 * First check whether an issue or PR already exists for your proposed change
 * Open an issue for non-trivial changes
 * Minimize scope: a pull request should cover one thing. Unrelated changes within a single PR will be asked to be split.
 * Automated checks, ensure all these pass before submitting.

## Review Policy

Contributions that do not follow these guidelines may be closed without detail. Once more, this is not to downplay your efforts, but a necessity to keep the projects manageable for the maintainer.
